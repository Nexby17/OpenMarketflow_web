## 1. Цель

Автоматический торговый робот на ликвидных акциях MOEX по стратегии **PSAR×EMA (H1, стандартная полярность)** — единственной конфигурации из всех акций-бэктестов, давшей устойчивый эдж на всех бумагах без подгонки под тикер.

## 3. Инструменты

11 тикеров: SBER, GAZP, LKOH, ROSN, GMKN, TATN, SNGS, MTSS, NVTK, PLZL, MTLR.

- Размер лота **не хардкодить** — брать из метаданных инструмента Finam API (в бэктесте GAZP LOT=10; у LKOH/GMKN/PLZL лотность другая).
- Один конфиг параметров на все тикеры (как в бэктесте). Список тикеров — конфиг, расширяемый.
- Требования к счёту: маржа и разрешённые шорты по всем тикерам (MTLR/LKOH — шорты критичны для доходности).

## 4. Рыночные данные

- **Источник:** Finam REST, бары H1, символ `{TIC}@MISX`. Токен уже в `HedgeFund/.env` (FINAM_API_KEY), JWT через `/v1/sessions`.
- **Сессия:** только основная, бары 10:00–18:40 МСК (07:00–15:40 UTC). Вечерка не используется.
- Опрос закрытого H1-бара: после закрытия часа + пауза 30–60с, с ретраями; **не использовать незакрытый бар**.
- История для прогрева: ≥300 H1-баров на тикер (SAR/EMA12/ATR14 сходятся; качать 30-дневными чанками — паттерн `download_h1.py`).
- Контроль качества: детект дыр/дублей баров, алерт при просрочке >2 баров.

## 5. Алгоритм стратегии (точно как в бэктесте)

**Индикаторы на закрытых H1-барах:**
- PSAR: af0=0.02, step=0.2, max=0.2
- EMA(12) close
- ATR: TR с EWM alpha=1/14; первый бар дня TR = High−Low (гэпы между сессиями не входят)

**Сигналы (std-полярность — НЕ перепутать, на SI/V8 инверт):**
- LONG: SAR пересёк EMA сверху вниз (prev SAR > prev EMA и SAR ≤ EMA)
- SHORT: SAR пересёк EMA снизу вверх (prev SAR < prev EMA и SAR ≥ EMA)

**Вход:**
- Сигнал считается на закрытии H1-бара → вход по рынку в начале следующего часа (в бэктесте — open следующего бара)
- 1 позиция на тикер, long и short, перевороты через выход→новый вход

**Стоп и выход:**
- Начальный стоп: entry ± 3×ATR (на момент входа)
- Трейлинг: стоп подтягивается к PSAR — long: stop = max(stop, SAR); short: stop = min(stop, SAR). Никогда не отдаляется.
- Выход: касание стопа внутри бара → по цене стопа; гэп через стоп на открытии → по цене открытия
- Овернайты и выходные: позиции переносятся, принудительного закрытия по сессии НЕТ

## 7. Риск-менеджмент

- Базово 1 лот/тикер (как в бэктесте). Оценка капитала на портфель — до запуска (1 лот LKOH/GMKN/PLZL дорогой).
- Kill-switch по дневному убытку портфеля — параметр, default выкл, значение задаёт Самурай.
- Проскальзывание/комиссия: заложить не хуже 0.05%/сторона, мониторить факт.
- **Отличие от бэктеста, решить на этапе проекта:** в бэктесте стоп виртуальный. В реале рекомендуется дублировать брокер-стоп (stop-market) на уровне стопа с подтяжкой по PSAR — защита от потери связи.

## 8. Инфраструктура

- Python 3, systemd-юнит `sarema-stocks.service`, порт **5083** (следующий свободный).
- API: `/status` (mode, позиции по тикерам, PnL, последний бар, сигналы), `/start`, `/stop`, `/pause`, `/params` — по образцу of-robot.
- Состояние персистить (позиции, стопы, параметры) — рестарт без потери состояния.
- PnL и лоты обязаны совпадать с брокером (закон от 20.07).
- Логи в journalctl; чистка `journalctl --vacuum-size=500M` при перезапусках по регламенту.
- Известные грабли Finam: rate-limited (рой ботов), «no response» ≠ не исполнен, кэш DP. Ордерный канал — по образцу существующих роботов (gRPC).
- UI-строка в дашборде (app.js) — этап 2, по образцу BR-строки.
