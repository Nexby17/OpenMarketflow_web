## 1. Цель

Автоматический торговый робот на ликвидных акциях MOEX по стратегии
**PSAR×EMA (H1, стандартная полярность) + R-сайзинг позиций** — конфигурации,
давшей устойчивый эдж на всех бумагах без подгонки под тикер и подтверждённой
портфельным R-бэктестом (03.10.2026).

## 2. Базис — результаты бэктестов

Источники: `gazp_sarema.py` (v4), `multi_sarema.py` (v5, walk-forward),
`stocks_sarema_rmm.py` (R-MM, 03.10.2026). Данные: Finam H1 `{TIC}_2Y_H1.csv`,
2 года (09.2024–09.2026), только основная сессия.

**Чемпион-конфиг:** H1, std-полярность, SAR(0.02/0.2/0.2), EMA(12), вход по кроссу
(open следующего бара), выход касанием PSAR (трейлинг), начальный стоп 3×ATR,
овернайты разрешены, один конфиг на все тикеры, издержки 0.05%/сторона.

Результаты:
- Пер-тикерно: **11/11 PF > 1** (PLZL 2.66 … SNGS 1.46); walk-forward **48/50 полугодий PF ≥ 1.0**
- R-портфель (10 бумаг): **5839 сделок, WR 46.5%, avgR +0.170, sumR +995.5R, DD 14.4R**
- Некомпаунд, старт 1М₽: risk 0.5% → +481%; risk 1% → +763%; risk 2% → +842%
- Стабильность: все 9 кварталов и все 10 тикеров avgR > 0

Отвергнутое (не переносить в робот): CVD/volume-spike внутридневка, импульсные
пробои, exit по кроссу/chandelier, инверт-полярность.

## 3. Инструменты

Базовый список 10 тикеров: SBER, GAZP, LKOH, ROSN, GMKN, TATN, SNGS, MTSS, NVTK, PLZL.

- Один конфиг параметров на все тикеры. Список тикеров — конфиг, расширяемый.
- MTLR — только после отдельного R-теста (в v5 пер-тикерно проходил).
- Размер лота **не хардкодить** — из метаданных Finam API (SBER/GAZP лот=10, LKOH/PLZL лот=1 и т.д.)
- Требования к счёту: маржа и разрешённые шорты по всем тикерам (шорты критичны: на падающих бумагах вся прибыль с шортов).

## 4. Рыночные данные

- **Источник:** Finam REST, бары H1, символ `{TIC}@MISX`. Токен в `HedgeFund/.env` (FINAM_API_KEY), JWT через `/v1/sessions`.
- **Сессия:** только основная, бары 10:00–18:40 МСК (07:00–15:40 UTC). Вечерка не используется.
- Опрос закрытого H1-бара: после закрытия часа + пауза 30–60с, ретраи; **незакрытый бар не использовать**.
- Прогрев: ≥300 H1-баров на тикер (SAR/EMA12/ATR14 сходятся); качать 30-дневными чанками (паттерн `download_h1.py`).
- Контроль качества: детект дыр/дублей баров, алерт при просрочке >2 баров.

## 5. Алгоритм стратегии (точно как в бэктесте)

**Индикаторы на закрытых H1-барах:**
- PSAR: af0=0.02, step=0.2, max=0.2
- EMA(12) close
- ATR: TR с EWM α=1/14; первый бар дня TR = High−Low (гэпы между сессиями не входят)

**Сигналы (std-полярность — НЕ перепутать, на SI/V8 инверт):**
- LONG: SAR пересёк EMA сверху вниз (prev SAR > prev EMA и SAR ≤ EMA)
- SHORT: SAR пересёк EMA снизу вверх (prev SAR < prev EMA и SAR ≥ EMA)

**Вход:**
- Сигнал на закрытии H1-бара → вход по рынку в начале следующего часа (в бэктесте — open следующего бара)
- 1 позиция на тикер, long и short, перевороты через выход→новый вход

**Стоп и выход:**
- Начальный стоп: entry ± 3×ATR (на момент входа)
- Трейлинг: long — stop = max(stop, SAR); short — stop = min(stop, SAR). Никогда не отдаляется
- Выход: касание стопа внутри бара → по цене стопа; гэп через стоп на открытии → по цене открытия
- Овернайты/выходные: позиции переносятся, принудительного закрытия НЕТ

## 6. R-менеджмент (новое в v1.1)

- **1R = база × risk_pct**; risk_pct default **1.0%** (бэктест-зона 0.5–2.0%)
- **База:** некомпаунд от стартового капитала (как в базовом портфеле бэктеста).
  Опция `compound=true` (пересчёт по закрытым сделкам) — только по команде Самурая
- **Размер:** lots = floor(1R / stop_dist), stop_dist = 3 × ATR сигнального бара
- **Кэп номинала:** номинал позиции ≤ base × max_pos_pct (default **40%**)
- **Лотность обязательна:** округление вниз до целых лотов инструмента
  (в бэктесте игнорировалась — допустимое отклонение от бэктеста, фиксировать в /status)
- При недостатке средств/кэпа — сигнал пропускается (в базовом портфеле бэктеста пропусков 0)

## 8. Риск-менеджмент

- Kill-switch по дневному убытку портфеля — параметр, default выкл, значение задаёт Самурай.
- Ориентир из бэктеста: DD 14.4R ≈ 14% базы при risk 1%; худший день базового портфеля — контролировать.
- Проскальзывание/комиссия: заложить не хуже 0.05%/сторона, мониторить факт (расхождение с моделью → алерт).
- **Отличие от бэктеста:** в бэктесте стоп виртуальный. В реале дублировать брокер-стоп
  (stop-market) на уровне стопа с подтяжкой по PSAR — защита от потери связи.

## 9. Инфраструктура

- Python 3, systemd-юнит `sarema-stocks.service`, порт **5084**.
- API: `/status` (mode, позиции по тикерам, R-статистика, PnL, последний бар, сигналы), `/start`, `/stop`, `/pause`, `/params` — по образцу of-robot.
- Состояние персистить (позиции, стопы, база R, параметры) — рестарт без потери состояния.
- PnL и лоты обязаны совпадать с брокером (закон от 20.07). Разделять PnL по роботам на счёте.
- Логи в journalctl; чистка `journalctl --vacuum-size=500M` при перезапусках по регламенту.
- Известные грабли Finam: rate-limited (рой ботов), «no response» ≠ не исполнен. Ордерный канал — по образцу существующих роботов.
- UI-строка в дашборде (app.js) — этап 2, по образцу BR-строки.
